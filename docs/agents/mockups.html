7 · Estado vacío: cómo conectar el primero

Primera vez en Agents: qué es, el comando para agregar el MCP y la promesa de seguridad en una línea.

Let your AI agents sign in, safely
Claude Code, Codex, Cursor or any MCP agent can use the accounts you allow — passwords and 2FA codes — without ever seeing them.
  1. In your terminal: npx -y @otpilot/mcp connect
  2. It shows a code. Approve it here when it appears, if the codes match.
  3. Allow the accounts it can use. Revoke anytime.

8 · Del lado del agente (Claude Code)

El modelo solo ve nombres de cuentas y resultados. Si falta un permiso, recibe pending_approval y le pide al usuario que apruebe en OTPilot.

claude — ~/code/acme
> Probá el login de staging y fijate si el dashboard carga los pagos ● otpilot.list_accounts() ⎿ GitHub (2FA, login) · AWS staging (2FA, login) · acme-db (password) ● otpilot.browser_login(account: "AWS staging") ⎿ pending_approval — approve "Claude Code → AWS staging" in OTPilot Necesito acceso a AWS staging. Aprobalo en OTPilot (ícono de la extensión) y sigo. ● otpilot.browser_login(account: "AWS staging") ⎿ signed_in — session saved to .otpilot/aws-staging.json (expires 1h) ● playwright.open("https://staging.acme.io/payments", storageState: ".otpilot/aws-staging.json") ⎿ 200 · 14 payments listed ● otpilot.run(command: "psql -h db.staging -c 'select count(*) from payments'", env: { PGPASSWORD: "acme-db/password" }) ⎿ count: 14 (secrets redacted from output) Listo: el login funciona y el dashboard muestra los 14 pagos, igual que la base. Nunca vi la contraseña ni el código 2FA.
