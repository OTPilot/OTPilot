OTPilot 2.2 · Secure files & SSH keys — mockups

Un archivo es un tipo de campo (file): cualquier ítem puede tener uno, y hay dos tipos nuevos armados alrededor de eso, SSH key y Secure file. Los bytes viajan dentro del ítem cifrado (hasta 64 KB por ítem), así que sync, sharing, colecciones, agentes y backup funcionan sin cambios en el servidor. Plan: docs/files/plan.md.

8 · Archivo demasiado grande

Fase 1 guarda los bytes dentro del ítem cifrado: tope de 64 KB por ítem (el registro del servidor admite 128 KiB y el archivo crece ×1.8 al cifrarse). Rechazo claro, nunca truncar. Archivos grandes (PDFs, scans) serían la fase 2: blobs cifrados en R2, en planes pagos.

pdf
passport-scan.pdf is 2.4 MB
OTPilot keeps files up to 64 KB for now: keys, certificates and config files. Larger documents are coming.

9 · Agentes: usar el archivo sin verlo

run acepta @file: el MCP escribe el archivo en un directorio temporal privado (0600), pasa la ruta y lo borra al terminar. El contenido se redacta de la salida. Con eso un agente sube un build con el .p8 o hace push con una deploy key.

claude — ~/code/acme-ios
> Subí el build 412 a TestFlight ● otpilot.list_accounts() ⎿ App Store Connect · CI (Key ID, Issuer ID, file: AuthKey_2X9R4HXF34.p8) Deploy key · acme-api (SSH key) ● otpilot.run(command: "fastlane pilot upload --ipa build/Acme.ipa", env: { ASC_KEY_PATH: "App Store Connect · CI/@file", ASC_KEY_ID: "App Store Connect · CI/Key ID", ASC_ISSUER_ID: "App Store Connect · CI/Issuer ID" }) ⎿ exit 0 — Successfully uploaded build 412 (key written to a private temp file for this run, then deleted) ● otpilot.run(command: "git push deploy main", env: { GIT_SSH_COMMAND: "ssh -i {Deploy key · acme-api/@file} -o IdentitiesOnly=yes" }) ⎿ exit 0 — main -> main Listo: build 412 en TestFlight y el deploy pusheado. Nunca vi la clave .p8 ni la SSH.

Decisiones

  1. Tope: 64 KB de archivos por ítem.
  2. Free: SSH keys y archivos son ítems como cualquier otro, cuentan dentro de los 50.
  3. .env → "Split into fields" (un campo oculto por variable) entra en la fase 1.
  4. Generar claves SSH (Ed25519 y RSA 4096) entra en la fase 1.
